# 架构与兼容边界

## 两层确定性

### 1. AE2 / JEI 批量计划

将每个概率写成最简分数，并取所有产物分母的最小公倍数作为执行次数。

例如一次处理包含：

- 固定产出 `1 Ingot`；
- `50% × 2 Dust`；
- `33.333…% × 1 Gem`（由适配器提供精确的 `1/3`）。

最小批次是 6 次，样板为：

- 输入：`6 Ore`；
- 输出：`6 Ingot + 6 Dust + 2 Gem`。

这部分算法可以完全通用，但“从原生配方中读取概率”的工作仍由模组适配器完成。JEI 的展示槽没有标准字段能可靠表示概率、独立抽取次数或关联的机器规则。

### 2. 真实机器产出

仅把 AE2 样板写成 `5 → 4` 不会改变机器自己的随机结果。如果机器实际只出了 3 个，AE2 合成任务会等待；如果出了 5 个，则会产生计划外余量。

要保证真实机器也确定，必须在机器原本执行概率判定的位置接管结果：

1. 以 `维度 + 方块位置 + 配方 ID + 输出槽` 作为稳定序列键；
2. 从世界存档读取该键的当前相位；
3. 用确定序列替代本次随机布尔结果；
4. 在机器提交处理结果后保存新相位。

这样可以保留原机器的耗能、耗时、升级、并行数和输入输出逻辑。

## 为什么不能全局拦截随机数

全局替换 `RandomSource.nextFloat()` 看似通用，实际上无法知道一次随机调用究竟属于概率产物、粒子效果、声音、故障、掉落还是其他逻辑。调用顺序也会随模组版本变化，容易导致存档行为漂移。因此不采用全局 RNG 劫持。

## 适配粒度

适配目标是“每个模组的中央概率实现”，不是每台机器。例如一个模组的所有机器都调用同一个 `rollOutput` 方法时，一个钩子即可覆盖全部；若不同配方类型各自实现概率，则需要数个适配器。

建议首批顺序：

1. Create（集中式 ProcessingOutput）；
2. Mekanism（按其概率输出模型接管）；
3. GTCEu Modern（概率产物与并行处理）；
4. Thermal Series；
5. 用户整合包中实际使用的其他机器模组。

## 多产物和副产物

每个概率输出拥有独立序列状态，支持：

- 固定主产物 + 概率副产物；
- 多个相互独立的概率产物；
- 单次成功产出多个物品；
- 不同分母的联合批量样板。

若原模组定义的是“多个结果只能选一个”而不是独立概率，则适配器必须把它描述成互斥分布，不能拆成独立布尔概率。后续 API 会为加权互斥输出单独建模。

## 安全限制

- 默认限制最大批次，避免多个大分母导致最小公倍数爆炸；
- 配方或模组版本变化后，旧序列状态需按版本键隔离；
- 多方块机器使用其主控制器位置作为机器键；
- 只有服务端拥有并推进序列状态，客户端只做展示。
